## 1. 本轮已确认与待确认

- **结果优先，取数路径待验证**：目标是准确的实际销售额及取消/退款解释。订单接口只是候选，允许使用其他获授权且可核对的退款、结算、账单等数据组合；具体取决于接口验证。不强制只能从订单接口统计，也不能重复扣减已净额化的数据。页面呈现标准指标、来源和口径，不要求运营选择底层技术接口。
- **默认规则无需填写**：系统提供统一底层规则。未配置的监控对象自动继承；只有用户明确保存有效自定义规则时才覆盖。恢复默认应清除对象覆盖并显示继承来源。部分填写的自定义配置应明确校验，不悄悄转成默认。
- **渠道**：飞书优先；短信仅作为备选规划，不在首版启用。原型现有邮件配置不再视为用户确认需求。本轮不发送任何真实消息。
- **花费累计周期已确认**：默认按每家店铺当地时区统计当天累计花费，从当地当天 00:00 至当前采样时刻；次日 00:00 进入新的累计周期，不跨天累加，也不删除历史记录。其他周期保留为可选方向，具体选项另行确定。经营报表期间、花费累计周期、默认趋势比较窗口是三个不同概念；当日累计规则不替代默认趋势规则的比较窗口。
- **配置对象**：用户要求明确功能对应关系，尚未确认最终粒度；见第 4 节设计建议。
- 默认趋势规则需要存在；原型中的 1h/50%、30m/30% 暂作为初始规则草案，基准算法、实际刷新粒度与边界需验证。无需让每位运营逐条填入这些底层参数。

## 2. 技术方案是否适合中台

**适合保留现有品牌和交互设计，采用 React/Next.js 前端 + NestJS 后端继续建设。Nest 与 React 不二选一。** React 用于 UI；Next.js 是基于 React 的应用框架；NestJS 用于 Node.js 业务后端。中台是业务组织方式，不限定某一个前端框架。

推荐保持既定分工：Next.js/React/TypeScript + Tailwind/shadcn 前端，NestJS 模块化业务 API，PostgreSQL、队列和独立 Worker 负责持久化、采集、规则计算、通知。先实现首版必要模块，不提前开发全量领域。

### 当前实际工程状态

- `apps/web/public/interactive-preview.html`：4313 行左右的独立 HTML/CSS/JavaScript 原型，使用本地样本、localStorage 和自制 Canvas 图表；浏览器可打开操作。
- `apps/web/src/app/`：17 个业务路由和 1 个登录页 TSX 文件，全部只有标题占位；没有实现原型中的业务界面。
- 缺 `apps/web/package.json`、根 layout、Next 配置/TypeScript 配置、安装锁文件及实际前端依赖。根 package.json 只是脚本声明，不能证明已安装 Next/React/shadcn。
- `packages/api-client` 仅有错误/分页接口类型，没有实际 HTTP 客户端或生成流程。OpenAPI 只有路径摘要，绝大多数操作缺 responses，缺完整请求/响应 schema，不是可联调契约。
- 没有实际后端、真实鉴权、平台采集或飞书投递实现。
- 实际运行 `pnpm --filter @yz-cube/web build`，返回 `No projects matched the filters`。即使命令退出码为 0，也没有编译任何 Web 项目，不能算 build 通过。

**结论**：不是将现成 React 工程简单换成“中台模式”，而是将已验证的原型设计落实成可运行、可维护的 React/Next.js 工程。保留视觉、流程与样本，不把单 HTML 整体塞进 React 或继续长期堆字符串。

官方依据：[React UI](https://react.dev/)、[NestJS 服务端框架](https://docs.nestjs.com/)。

## 3. 首版功能逐项判定

判定区分“现有原型交互”和“正式可交付功能”。“已满足”仅限已检查的原型能力；真实数据/后端接入均尚未满足，不因页面存在或模拟回执而宣布业务上线。

| 核心需求 | 原型判定 | 证据/差距 | 正式交付判定 |
|---|---|---|---|
| 集中看销售额、费用、占比与图表 | 已满足（展示） | 驾驶舱、三费、趋势可渲染 | 未满足：TSX 占位、无真实查询 |
| 原始/取消/退款/实际销售额拆分 | 已满足（展示） | 有卡片、瀑布和样本明细 | 未满足：数据源、去重和口径待验证 |
| 不局限订单接口、按实际能力组合来源 | 未满足 | 固定订单拆分叙述，无实际数据适配或来源链路 | 未满足：需补统一指标与可追溯来源 |
| 分别展示站内、Meta、联盟佣金及合计 | 已满足（展示） | 三类样本与合计均在营销分析页面 | 未满足：无真实采集与核对 |
| 实际费用/费用率可信状态 | 未满足（仅部分覆盖） | 有赠金待核定标签，但计算将未知抵扣按 0 处理，仍显示精确合计/占比 | 未满足：未知必须传递，不能当真实净花费 |
| 每月销售额和费用、所选期间一致 | 未满足 | 仅 today/yesterday/7d/30d；没有自然月/自选区间。日期用固定倍率改汇总，分店表仍用原始总额 | 未满足：需自然月/自选时间及统一期间查询 |
| 仅监控在投站内广告、列表到详情 | 已满足（原型） | 在投列表有计划、关联 SKU、花费、ROI、详情和趋势 | 未满足：无真实在投状态/采样 |
| 未配置自动默认、无需填阈值 | 未满足（仅部分覆盖） | 有 DEFAULT/CUSTOM 和默认样本；切 DEFAULT 后清空三字段，表单 checkValidity=false | 未满足：修默认表单、继承/覆盖与计算 |
| 单对象三个参数、自定义 AND 条件 | 已满足（计划级原型） | 保存 cap=5000、ROI=4 后可从 localStorage 回读；风险更新 P0 | 未满足：无后端持久化、运行规则和权限 |
| 按商品分别配置、对象清晰 | 未满足 | 编辑器 targetAdId/bindLevel=CAMPAIGN；展示多 SKU 但不能逐商品配置 | 未满足：先验证可用粒度，再交付对应对象功能 |
| 默认当天花费、其他周期可选 | 未满足 | 只有 todaySpend 及当日文案，没有周期字段/选择器或跨日处理；已确认默认按店铺当地自然日累计，次日重新累计 | 未满足：补周期、当地午夜边界及历史回放；其他可选周期另行细化 |
| 飞书优先、短信备用 | 未满足（仅有飞书模拟页面） | 当前页面飞书+邮件；测试函数直接写死“送达成功”，没有网络调用；没有短信备用状态 | 未满足：飞书真实通道及投递状态，短信暂不启用 |
| 告警认领/处理与历史 | 已满足（原型交互） | 认领后 localStorage 状态为 PROCESSING；有关闭/备注流程 | 未满足：事件生成、幂等、真实通知/权限未接入 |
| 功能聚焦、未来规划入口关闭 | 已满足（本轮轻量修改后） | 两个蓝图入口不可见；四个非核心独立菜单隐藏；核心页可渲染 | 正式壳尚未实现，未来迁移时沿用范围配置 |

不存在“全套首版已满足”的结论：原型覆盖了大部分展示和部分操作，尚未达到正式前端及业务闭环交付。

## 4. 配置对象对应的具体功能点（建议，待方向确认）

业务上配置的是“某店铺中可监控的具体广告投放对象”，不能仅用全局商品名或仓库 SKU 当主键。

1. **列表定位**：展示店铺、广告计划 ID/名称、投放对象类型与 ID、关联平台商品。允许从广告行进入该对象规则。
2. **粒度支持**：若接口提供计划下商品的可比消耗/ROI，支持商品级覆盖；若只有计划级，明确显示“计划级，覆盖关联商品”，商品级配置不可用并解释原因。关联 SKU 不代表已有 SKU 级指标。
3. **规则编辑**：继承默认 / 自定义；默认时不必填参数；自定义配置每日预算参考值、目标 ROI、花费上限，保存前显示适用店铺和对象。预算字段的必填性不应阻止默认模式保存。
4. **规则范围**：以组织、店铺、计划、对象类型/ID 构成稳定身份；全局默认是兜底，对象覆盖优先，恢复默认可回读。计划级与商品级不得对同一监控目标重复执行两套覆盖规则；具体层级优先关系随粒度确定。
5. **执行解释**：广告详情与告警证据显示实际生效规则、对象、时间范围、花费和 ROI、采样截至时间，支持回看当时版本。

这对应“广告列表 + 详情 + 规则编辑 + 告警证据”四处功能，不需要扩成商品中心或库存 SKU 管理模块。

## 6. 缺项的实施顺序

**先补最高优先级经营统计**：最小可运行前端工程 → 可替换 Mock/HTTP 的 API 层 → 自然月/自选日期与明细/汇总/导出一致 → 统一指标来源和可信状态 → 真实授权、接口验证及样本对账。数据层可利用不同获授权接口组合，界面不绑定某个取数接口。

**再补首版广告闭环**：无需填写的默认继承 → 对象选择和能力粒度提示 → 自定义三个参数/AND 条件/恢复默认 → 累计周期（店铺当地当天，次日重新累计）→ 采样新鲜度与缺数据处理 → 规则运行生成事件 → 飞书真实投递、失败重试/冷却与人工处置。短信仅保留备用状态，不建设额外短信通道。

本轮实际修改仅为菜单隐藏、README 真实状态说明和本核对报告；上述功能缺项未在本轮实现。后续正式多文件实现需按 AEG 建立/续接 Session、定义范围、验收并保留证据。

- 源码盘点：核对所有 TSX、根脚本、OpenAPI、client 类型、静态原型关键处理函数；未发现可运行 Next.js Web 包/后端。
