# Shopee 首版：无真实账号的验证结果

日期：2026-10-16。范围：经营统计、广告预警。没有调用真实或沙箱 OpenAPI，没有修改店铺、开通广告或发送飞书。

本文验证的是文档约束、参考公式与构造反例；**不代表现有前后端实现已经测试通过，也不代表平台数据已实测满足。** 当前任务没有修改产品代码。

## 1. 已执行与结果

| 检查项 | 本次怎么验证 | 结果与剩余限制 |
|---|---|---|
| 销售额计算路径 | 对照已核查的订单/退款/结算字段，分别计算原始金额扣减路径与已净额路径；用重复退款样本检查去重 | 公式案例通过；已净额不能再减退款。平台状态到“财务已生效”的映射仍待实数确认 |
| 赠金反推 | 构造发放、使用、到期、撤回、退回余额的流水，再核对余额守恒；额外运行 500 组生成流水 | 完整流水条件下可反推；缺少任何重要变动不能默认填 0。证明只看总余额不能唯一拆分现金/赠金 |
| 付费/Meta 钱包反推 | 构造充值、消费、消费退款、退回支付渠道、期末余额 | 公式案例通过；充值及退回银行卡不能当消费。Meta 实际字段完整度未验证 |
| 累计 ROAS 半小时下降 | 计算 8→5、恰好下降 30%、超过 30%、零基准/零消耗 | 快照公式可用；“超 30%”采用严格大于。源更新速度未验证，规则解释仍为设计候选 |
| 花费上限 AND ROAS 目标 | 两条件分别真/假及等于边界 | 花费达到上限包含等于；ROAS 低于目标不包含等于；只满足一项不能触发 |
| 1 小时花费增长 | 用 -120/-60/当前三个时点算两个滚动窗口，并检查 50% 边界 | 计算案例通过；只有两次累计快照不足以完成“本小时对上一小时”的完整比较。业务基准仍待确定 |
| 快照可比性 | 检查店铺/活动/币种/统计日/归因口径、采样间隔、负差值；用迟到 GMV 构造反例 | 不同对象/口径不能混比；跨日须拼接，当前验证直接拒绝跨日比较；GMV 差值不能无条件当区间独立产出 |
| 费用率与金额 | 十进制金额累计、整单/子项佣金不重复、缺费用源、零销售额 | 案例通过；未知费用不能填 0，零销售额不能给出有限费用率；尚未确认各币种单位与税费实值 |
| 沙箱可用范围 | 紫鸟读取官方 Sandbox Testing V2 原文，核对前置条件与模块清单 | 文档确认需要测试 App、测试账号及授权；可不依赖真实店铺做部分订单链路测试，但不等于无需任何账号 |

## 2. 无真实数据也能确定的四个结论

1. **半小时累计 ROAS 变化可以用快照比较。** 前提是源在相应时间内确实更新；离线只能证明算法，不能证明源时效。若要求“最近半小时独立投放的 ROAS”，还需解决归因与迟到转化。
2. **赠金使用可以反推，但输入必须完整。** 到期/撤回不应算成消耗，收到的赠金也不等于已经使用。退款后净额与原始消耗的口径不能混用。
3. **只有总余额无法唯一求解现金消耗。** 构造反例：期初总余额都为 200、期末都为 40、总消耗都为 160。账户 A 原有现金 100、赠金 100，消耗现金 60、赠金 100；账户 B 原有现金 160、赠金 40，消耗现金 120、赠金 40。已知合计完全相同，现金花费不同，必须补至少一种余额拆分或使用明细。
4. **增加采样不能制造源里没有的变化。** 源未刷新时，快照差为 0，现实投放仍可能继续；历史 GMV 回补时，快照增量也可能混入旧点击转化。这是对算法适用边界的验证，不能靠更多构造案例消除。

## 3. 官方沙箱核查

官方来源：[Sandbox Testing V2](https://open.shopee.com/developer-guide/644)，页面更新日期 2025-09-16；本次在紫鸟直接读取正文。

- 前置要求：创建测试 App、Sandbox Shop/Merchant Account，并授权给测试 Partner ID；测试登录账号与真实店铺账号不同。
- 支持表列出 Product、Global Product、Media Space、Order、Logistics、First Mile、Shop、Merchant 等核心模块；可使用 Console 的 API Test Tools，创建测试订单及推进订单状态。
- **该表没有列出 Ads、AMS、Payment、Returns。** 因此它不能作为这些模块已支持沙箱的证据；“文档未列明”不等于确认永不支持。
- 没有测试 App/测试账号的前提下，本次未做沙箱调用；也没有把文档示例当作沙箱实际返回。

结论：没有真实数据店铺，不妨碍公式实验与文档校验；若有开发者测试环境，可以进一步做官方订单链路联调。但不能靠沙箱直接证明真实广告更新延迟、赠金实际分摊和 Meta 账单准确性。

## 4. 仍须真实数据或账号才能关闭的项目

| 项目 | 为什么当前不能替代 | 以后最小验证材料 |
|---|---|---|
| 实际 App 权限及目标店铺字段返回 | 文档权限类别不等于目标 App 实际获批；白名单/站点差异无法用构造数据证明 | 已授权测试/正式 App 的实际响应与权限结果 |
| 取消、退款的生效金额与归属期 | 公式无法判断平台状态实际对应哪笔资金变化 | 少量整单取消、部分取消、部分退款、完结后退款、跨月退款样本及对账 |
| 赠金变动源是否完整 | 余额守恒只在增减事件完整时能还原消费 | 有充值、赠金使用、到期/回扣的余额和明细样本 |
| Meta 费用字段及取数路径 | 当前店铺未开通，只有产品入口与指南，无法确认真实列结构 | 已开通店铺的一份费用日报/交易记录及取数入口 |
| 日内更新与 30m/1h 提醒是否及时 | 本地快照实验不能测出平台真实延迟 | 一个有实际消耗活动的连续采样与后台对照 |
| Shop GMV Max 的状态与快照可用性 | 区间接口没有完整状态承诺，当前无活动样本 | 一个真实 GMS 活动的 ID、状态、设置和连续表现返回 |
| 飞书真实送达 | 本次未接入/使用通知凭据，也没有发送消息授权 | 配置好的通知渠道及另行获准的测试投递；本次未执行 |

## 5. 给前端设计的已验证边界

可以先固定：金额按十进制处理；缺数据、无数据、零金额分开；总额/明细不重复计入；快照展示统计对象、归因口径与采样时间；规则区分严格大于/达到；未知来源不显示精确总费用率。

暂不固定：默认增长比较基准、累计 ROAS 与区间独立 ROAS 的最终选择、跨月退款统计方式、真实刷新频率、Meta 接入方式、GMS 状态读取路径。它们分别需要业务决定或外部数据验证，不属于本轮公式检查可以证明的内容。
